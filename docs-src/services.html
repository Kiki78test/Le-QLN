Règles d'or

  • Double authentification sur GitHub, Render, Google, Apple, Cloudflare, Resend.
  • Une clé secrète ne se colle que dans Render → Environment ou GitHub → Settings → Secrets, jamais dans une conversation, un e-mail ou le code.
  • Clé exposée par erreur : la révoquer dans le service, en créer une nouvelle, la remplacer (Render redémarre tout seul).
  • Ne jamais changer SECRET sur Render : tous les joueurs seraient déconnectés.
  • Une seule instance Render : salons multijoueur et compteurs anti-abus vivent en mémoire du serveur.
  • Ne jamais renommer les clés de stockage qln: / qln-en: de l'appli, même en changeant le nom du jeu : les joueurs perdraient leur progression.

2. Render — serveur et base de données

Ce qui tourne

Créé par le Blueprint render.yaml (projet Le-QLN, séparé d'Airmony).

  • Web service le-qln : Node, région Francfort, cd server && npm install --omit=dev puis cd server && npm start. Adresse : https://le-qln.onrender.com. Santé : /sante.
  • Redéploiement automatique à chaque envoi touchant server/, analyse.js ou les dictionnaires (data/, en/data/), seulement si les tests GitHub passent (autoDeployTrigger: checksPass).
  • Offre Free : s'endort après 15 min sans visite (premier réveil ≈ 30 s). Passer en Starter (7 $/mois) à l'ouverture au public.
  • Base le-qln-db (PostgreSQL, Francfort, base qln, utilisateur qln) : accessible seulement depuis Render. Offre Free actuelle : expire 30 jours après sa création (+14 jours de grâce), 1 Go, sans sauvegarde → passer en Basic 256 Mo (≈ 6 $/mois, sauvegardes quotidiennes) avant le 10 décembre 2026.

⚠ Ne jamais supprimer la base ni changer sa région : comptes, progression et scores seraient perdus.

Multijoueur (WebSocket wss://le-qln.onrender.com/ws)

Relais : le serveur ne joue pas, il transmet. L'hôte de chaque salon détient l'état et le diffuse.

  • Messages au serveur : annuaire / annuaire-stop (liste des salons en attente + nombre de joueurs en ligne), entrer (rejoindre ou créer un canal), publier (résumé public du salon, nettoyé et borné par le serveur), sortir ; tout autre message est relayé aux membres du salon.
  • Nettoyage toutes les 30 s : connexions muettes coupées, salons inactifs depuis 2 h fermés. Origines acceptées : variable ORIGINES.
  • Partie rapide : choisie côté appli (salon le plus rempli, sinon salon automatique qui démarre seul).

Anti-triche (server/jour.js)

Le serveur lit les mêmes dictionnaires que l'appli et refait le tirage du défi du jour (graine = date).

  • Refus si : cartes différentes de celles du jour, mot qui n'est pas une anagramme de sa carte, doublon, score au-dessus du maximum possible avec ces mots.
  • Défi libre : mots vérifiés, maximum plus large. Braquage : score borné. Les chronos ne sont pas rejoués.

7. Tests en local

  • Serveur : cd server && DATABASE_URL=postgresql://…?sslmode=disable PORT=8790 node index.js puis cd tests && QLN_TEST_URL=http://localhost:8790 node --test serveur.test.js.
  • Appli : servir la racine (python3 -m http.server 8765) puis QLN_SITE=http://localhost:8765 node --test --test-concurrency=1 appli.test.js (ajouter QLN_TEST_URL pour les tests avec serveur).
  • Les tests remplacent toujours config.js : ils ne touchent jamais au vrai serveur.
